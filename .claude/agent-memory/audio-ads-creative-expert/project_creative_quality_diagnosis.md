User flagged on 2026-04-24 that creative output is flat — scripts boring, acting instructions don't bring out peak emotion — even though the per-version KnowledgeContext snapshot work landed correctly and ElevenLabs tag emission (`[rapid-fire][fast]`, opening stacks) is now firing properly on iteration.

**Why:** The bottleneck moved upstream from syntax to creative direction. The current `getBaseSystemPrompt` in `src/lib/knowledge/builder.ts` is structurally a _process compliance prompt_ (numbered tool order, hard rules, "Script Guidelines" reduced to 4 generic bullets). The provider modules (`elevenlabs-voice.ts`, `openai-voice.ts`, `simple-voice.ts`, `bytedance-voice.ts`) teach _syntax_ — bracket grammar, field schemas, baseline tone enums — not creative direction. The word "creative" appears once in the role line. There's no taste function (no banned phrases, no banned openings, no negative space), no duration-specific arc structure (15s vs 30s treated identically), and no model for what makes an acting direction _land_ vs sit flat ("Tone: enthusiastic" vs "Voice Affect: a line cook at the end of a Friday rush").

**How to apply:** When the user asks about creative output quality, do NOT propose tuning the existing bullets or injecting more examples into provider modules. Propose a structural split: a new top-of-prompt creative-direction module (persona with hate/love list, listener target, duration arcs, banned phrases, casting-direction-first principle, flat-vs-landed acting examples) running BEFORE provider modules, with provider modules demoted to "translate the casting direction into our syntax." `getBaseSystemPrompt` should keep only the operational contract (tool order, hard rules, title). Persist the prose casting direction in the version snapshot alongside pacing/accent/provider/format so iteration inherits creative _intent_, not just _output_. Also: the Lahajati persona-prompt format ("اقرأ بصوت واثق كأنك مذيع رياضي") is the right mental model for ALL providers — character work first, syntax second; ElevenLabs/OpenAI's tag-and-field formats accidentally suppress character because they optimize for control.
