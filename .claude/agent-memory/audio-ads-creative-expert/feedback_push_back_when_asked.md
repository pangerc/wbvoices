User explicitly invites pushback in long-form requests ("challenge my assumption", "push back, if you think any of this is wrong-headed say so"). When this framing appears, do not soften the disagreement to be polite.

**Why:** They are using the conversation to stress-test their own thinking before committing to a direction. Validation is worthless to them in that mode; the only useful response is the strongest counter-position the evidence supports. They have a memory entry already (`feedback_deep_planning.md`) showing they want lifecycle/UI/precedence questions exhausted before plan approval — same impulse: surface the disagreement now, not after the work is done.

**How to apply:** When the framing is "challenge / push back / disagree if you think X" and the evidence supports a counter-position, lead with the disagreement in plain language ("you are right that A, you are wrong if you think B"). Then justify with file/code evidence. Do not hedge ("you make some good points but consider..."). Do not validate first and then disagree — the validation gets weighted as the answer. Save the structural recommendation for the end, after the disagreement has done its work.
